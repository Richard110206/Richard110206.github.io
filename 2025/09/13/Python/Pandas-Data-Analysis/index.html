场景推荐方式
数据是从 JSON / API / 字典里来的字典构造（直接传 data=dict）
数据是从手动列举、CSV 解析、矩阵运算来的嵌套列表构造（按行写入更自然）

慎用 dropna() 一刀切

本例直接 dropna() 把 1082 行砍到 126 行，丢失了 88% 的数据，几乎一定是错的。正确做法通常是：

  • 对关键列（如标签 胎儿是否健康）用 dropna(subset=[...]) 删
  • 对非关键列（如某些次要指标）用 fillna() 填补
  • 对整列大部分都缺失的列（如本例的「染色体的非整倍体」），考虑直接 drop(axis=1) 删列

填充策略怎么选？

场景推荐策略
数值列，分布接近正态用 均值
数值列，有离群点用 中位数（鲁棒）
分类 / 字符串列用 众数（mode()）或固定值如 '未知'

永远不要用全局均值填充所有缺失——会扭曲数据分布。分组填充（groupby + transform）几乎总是更好的选择。

五、数据筛选与排序

清洗完数据后，最常做的两件事就是按条件查行和按字段排序。

loc 与 iloc：两种取行 / 取列的方式

loc vs iloc 最容易踩的坑

  • loc 的切片是闭区间：df.loc[0:5] 含第 5 行
  • iloc 的切片是左闭右开：df.iloc[0:5] 不含第 5 行（和 Python 列表一致）

记忆口诀：「标签闭合，位置开」。如果你重置过索引（df.reset_index(drop=True)），两者在整数下标上的行为差异就只剩切片区间了。

concat：物理拼接

把多张表纵向或横向拼起来，类似 SQL 的 UNION：

merge：按关键列连接

类似 SQL 的 JOIN，根据某列把两张表按行对齐：

how 参数 SQL 对应 行为
inner INNER JOIN 只保留两表都有的键
left LEFT JOIN 保留左表全部，右表无则填 NaN
right RIGHT JOIN 保留右表全部
outer FULL OUTER JOIN 两表键的并集

何时用 concat，何时用 merge？

  • concat：两张表结构相同（列名一样或行索引一样），只是想堆叠起来 → 像把多块乐高拼成一根长条
  • merge：两张表结构不同，需要按某个键（如 ID）对应起来 → 像用「孕妇代码」把基本信息和检测结果粘在一起

简记：「同构堆叠用 concat，异构关联用 merge」。

十、常用技巧速查

新手最常见的 5 个坑

  1. SettingWithCopyWarning：切片后直接赋值会报警告 → 用 .copy() 显式拷贝，或用 .loc[] 赋值
  2. iloc 当 loc 用：索引被重置过后很容易搞混 → 牢记「位置用 iloc，标签用 loc」
  3. 忘记 inplace=True / 不接收返回值：很多方法默认返回新对象，不修改原对象 → 要么接 df = df.dropna()，要么 df.dropna(inplace=True)
  4. groupby 后忘了重置索引：reset_index() 把分组列从索引变回普通列，后续才能继续筛选
  5. pd.cut 分箱后 groupby 出现空组：加上 observed=True 避免显示空分组
