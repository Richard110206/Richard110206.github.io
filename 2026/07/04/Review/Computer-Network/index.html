第1章 计算机网络绪论

1.1 计算机网络的定义

计算机网络是指将地理位置不同的具有独立功能的多台计算机及其外部设备，通过通信线路连接起来，在网络操作系统、网络管理软件及网络通信协议的管理和协调下，实现资源共享和信息传递的计算机系统。

定义三要素：

  1. 自主计算机——具有联网能力的独立计算机（独立配置、独立工作、自由进退）
  2. 规范互连——任意两两之间物理相通、逻辑沟通
  3. 共享资源——彼此互享、公共分享（计算能力、存储空间、信道带宽、信息数据）

  1. 节点的物理连接及信号传输

1.4 网络性能指标

高频考点：时延计算、带宽与吞吐量、信道利用率

时延（delay/latency）= 发送时延 + 传播时延 + 处理时延 + 排队时延

【作业题】 收发两端之间的传输距离为1000km，信号在媒体上的传播速率为2×10⁸ m/s。试计算以下情况的发送时延和传播时延：

（1）数据长度为10⁷ bit，数据发送速率为100kbit/s。

（2）数据长度为10³ bit，数据发送速率为1Gbit/s。

（3）从以上计算结果可得出什么结论？

解答：

（1）发送时延 = 数据长度/发送速率 = 10⁷/(100×10³) = 100s

传播时延 = 传输距离/传播速率 = 1000×10³/(2×10⁸) = 5×10⁻³s = 5ms

（2）发送时延 = 10³/(10⁹) = 10⁻⁶s = 1μs

传播时延 = 1000×10³/(2×10⁸) = 5×10⁻³s = 5ms

（3）电磁波在同种媒体上传播距离不变时传播时延相同，与数据的发送速率无关。但数据长度越长，发送速率越慢则需要的发送时延越长。

【作业题】 试计算一个包括5段链路的运输连接的单程端到端时延（以ms为单位）。5段链路中有2段是卫星链路，有3段是广域网链路。每条卫星链路由上行链路和下行链路组成，传播时延之和为250ms。每个广域网范围为1500km，传播时延按150000km/s计算。各数据链路速率为48kbits/s，帧长为960bits。

解答：

（1）卫星链路单程传播时延 = 250ms，两段卫星 = 250×2 = 500ms

（2）广域网单程传播时延 = 1500/150000 = 10×10⁻³s = 10ms，三段广域网 = 10×3 = 30ms

（3）每段链路发送时延 = 960/(48×10³) = 0.02s = 20ms，五段链路 = 20×5 = 100ms

（4）总时延 = 500 + 30 + 100 = 630ms

指标 定义
速率 数据传送速率（额定数据率）
带宽 单位时间网络中某信道能通过的最高数据率
吞吐量 单位时间通过某个网络（信道、接口）的数据量
发送时延 主机或路由器发送数据帧所需时间 = 数据帧长度/信道带宽
传播时延 电磁波在信道中传播一定距离所需时间 = 信道长度/电磁波传播速率
处理时延 主机或路由器处理分组（分析首部、查找路由等）花费的时间
排队时延 分组在路由器输入输出队列中排队等待的时间
时延带宽积 = 传播时延 × 带宽 表示链路可容纳的最大比特数
往返时延 RTT 从发送方发送数据到收到确认所经历的总时间
信道利用率 信道有数据通过的时间百分比

时延与利用率关系： $D = D_0 / (1 - U)$，利用率U增大时，时延D迅速增大。

1.5 三种交换方式

重点：三种交换方式的对比、电路交换三个阶段

特性电路交换报文交换分组交换
原理建立连接→通话→释放连接整个报文存储转发报文切分为分组，逐个存储转发
是否建立连接是（独占线路）否否
线路利用率低（通信期间独占）高高
时延建立连接后传输快较大（整个报文存储转发）较小（分组短，并行转发）
可靠性连接断开则通信中断较好好（可绕行）
资源分配静态（预分配带宽）动态动态
适用场景实时电话电报互联网（数据通信）

1. 电路交换： 通信前先建立一条专用的端到端物理通路，通信期间独占。三个阶段：建立连接 → 数据传输 → 释放连接。

  • 优点：建立连接后传输速率快，延迟稳定
  • 缺点：线路利用率低，建立连接时间长，不适合突发数据

2. 报文交换： 以整个报文为单位进行存储转发，不建立连接。

  • 优点：线路利用率高，不需要建立连接
  • 缺点：报文可能很长，存储转发时延大，对缓存要求高

3. 分组交换： 将报文切分为较短的分组，每个分组独立存储转发。

  • 优点：时延小（分组短），灵活性高，线路利用率高
  • 缺点：有额外开销（每个分组都要加首部），可能乱序到达

【2025夏 · 简答2】电路交换、报文交换、分组交换优缺点。

三种交换的核心区别：电路交换建立端到端专用通路，报文交换以整个报文存储转发，分组交换将报文切分为分组逐个存储转发。详见上方对比表。

【作业题】 长度为100字节的应用层数据交给运输层传送，需加上20字节的TCP首部，再交给网络层传送，继续加上20字节的IP首部，最后交给数据链路层的以太网传送，以太网的首部和尾部共18字节。试求数据的传输效率。

【2024春 · 简答1】TCP/IP和OSI模型的优缺点，内容，联系。

OSI模型的优缺点：

  • 优点: 层次清晰，概念完整，服务/接口/协议三者分离，理论价值高
  • 缺点: 严格分层导致效率低，某些功能在不同层重复出现；实现复杂，实际未完全商业化

TCP/IP模型的优缺点：

  • 优点: 实用性强，先有协议后有模型，是互联网的实际标准；网络接口层兼容各种底层网络
  • 缺点: 网络接口层定义模糊，没有明确区分物理层和数据链路层；模型层次少，某些功能界定不清

两者联系：

  • 都采用分层体系结构
  • 都基于独立协议栈的概念
  • 都能实现异构网络互联
  • 五层模型综合了两者的优点，便于教学

为什么要分层？

分层的好处：

  1. 各层之间相互独立（上层不需要知道下层如何实现）
  2. 灵活性好（某一层技术变化不影响其他层）
  3. 结构上可分割
  4. 易于实现和维护
  5. 能促进标准化工作

分层的坏处：

  1. 降低效率（层层封装/解封装有开销）
  2. 有些功能会在不同层次中重复出现

层次多少的权衡：层数太少 → 每一层协议太复杂；层数太多 → 描述和综合各层功能时困难较多

C/S方式与P2P方式：

  • C/S（客户/服务器）：主动-被动模式，客户请求，服务器提供服务
  • P2P（对等连接）：双方都是客户和服务器，本质仍是C/S方式

第2章 物理层

2.1 物理层的基本概念

物理层要尽可能屏蔽掉物理设备和传输媒体、通信手段的不同，使数据链路层感觉不到这些差异。主要任务是确定与传输媒体接口的机械、电气、功能和规程特性。

2.2 数据通信理论基础

必考点：奈氏准则和香农公式

奈氏准则（理想低通信道）： $C = 2W \log_2 V$ (bit/s)

  • W = 理想低通信道带宽(Hz)
  • V = 码元种类数
  • 给定带宽下，码元传输速率有上限，否则码间串扰

香农公式（有噪声信道）： $C = W \log_2(1 + S/N)$ (bit/s)

  • W = 信道带宽(Hz)
  • S/N = 信噪比（用分贝表示：信噪比dB = $10 \log_{10}(S/N)$）
  • 带宽或信噪比越大，极限传输速率越高
  • 只要低于极限速率，一定能找到无差错传输方法

【作业题】 假定信道带宽为3100Hz，最大信息传输速率为35kbit/s，请用香农公式计算：

（1）若想使最大信息传输速率增加60%，问信噪比S/N应增大到多少倍？

（2）如果在（1）基础上将信噪比S/N再增大到10倍，问最大信息速率能否再增加20%？

解答：

（1）$C_1 = 35 \text{ kbit/s}$，由 $C = W\log_2(1+S/N)$：$S/N_1 = 2^{C_1/W}-1 \approx 2502.97$

$C_2 = 1.6 \times C_1 = 56 \text{ kbit/s}$，$S/N_2 = 2^{C_2/W}-1 \approx 273275.14$

S/N应增大到约109倍（$273275.14/2502.97 \approx 109.18$）

（2）$S/N_3 = 10 \times S/N_2$，$C_3 = W\log_2(1+S/N_3)$

增加比例约7.7%，不能再增加20%。

2.3 基带编码方式

【某年真题 · 简答4】以太网中的基带编码有哪些？

以太网使用的基带编码主要有以下四种：

编码方式规则特点
不归零制（NRZ）高电平=1，低电平=0，直接转换不经零电平简单，但无时钟同步，长串0/1易失步
归零制（RZ）正脉冲=1，负脉冲=0，每个码元中间回到零电平有时钟信息，但频带利用率低
曼彻斯特编码位中间跳变：上升沿=0，下降沿=1（也可反过来）自带时钟同步，效率50%（频带宽度加倍）
差分曼彻斯特编码位中间必跳变；位开始边界：前半个码片与前一个码片后半相同=1，取反=0自带时钟同步，抗干扰好（判决依据是边界变化而非电平绝对值）

注意: 10Mb/s以太网采用曼彻斯特编码，波特率 = 数据率 × 2 = 20 MBaud。

【2025夏 · 计算4】码元率10000，划分为8个振幅，求数据传输率。

解答：

由奈氏准则：$C = B \log_2 V$

其中波特率 $B = 10000$ Baud，码元种类数 $V = 8$

数据传输率 $C = 10000 \times \log_2 8 = 10000 \times 3 = $ 30000 bit/s = 30 kbit/s

【作业题】 （1）画出数字信息011101001的曼彻斯特编码和差分曼彻斯特编码。

（2）10Mb/s以太网的码元传输速率是多少？

解答：

（1）曼彻斯特编码：每个码元中心有跳变，高→低=1，低→高=0。

差分曼彻斯特编码：码元前沿有跳变=0，无跳变=1。

（2）波特率 = 数据率 × 2 = 20 MBaud（曼彻斯特编码每个码元用两个信号周期）

2.4 信道复用技术

重点：四种复用方式的原理与区别

复用方式原理
频分复用FDM将总带宽分割成若干子信道，每路信号占用不同频段
时分复用TDM将时间划分为等长TDM帧，每用户占用固定时隙。可能造成线路浪费
统计时分复用STDM按需动态分配时隙，提高利用率
波分复用WDM光的频分复用，一根光纤同时传输多个不同波长的光载波信号
码分复用CDM(CDMA)各用户使用不同码型，同一时间使用同一频带，码片序列必须相互正交

CDMA要点：

规则1——编码规则：

  • 每个站分配唯一的 m bit 码片序列，各站码片必须互相正交（规格化内积=0）
  • 发送比特1 → 发送码片序列本身
  • 发送比特0 → 发送码片序列的反码（每个比特取反）
  • 不发送 → 不发送任何信号（即全0）
  • 例如S站码片为00011011 → 向量(-1,-1,-1,+1,+1,-1,+1,+1)

规则2——空中叠加规则：

  • 所有站点共用同一信道，多个站同时发送时，空中信号是线性叠加
  • 数学上就是对应对应位置数字直接相加（不是异或，是代数加法）
  • 例：A发送(+1,+1)且B发送(-1,+1)，则叠加后空中信号 = (0,+2)

规则3——解码规则（规格化内积）：

  • 将收到的叠加序列与某站码片序列做规格化内积（点积 ÷ m）
  • 自己和自己的内积 = +1（发送了比特1）
  • 自己和反码的内积 = -1（发送了比特0）
  • 与正交的其他站内积 = 0（未发送）

【作业题】 假设4个站的码片序列分别为：

A: (-1,-1,-1,+1,+1,-1,+1,+1)　B: (-1,-1,+1,-1,+1,+1,+1,-1)

C: (-1,+1,-1,+1,+1,+1,-1,+1)　D: (-1,+1,-1,-1,-1,-1,+1,-1)

（1）现收到码片序列：(-1,+1,-3,+1,-1,-3,+1,+1)。问哪个站发送了什么数据？

（2）假定A、B和C站同时发送比特0，请计算发送结果产生的码片序列。

解答：

（1）将收到的序列与各站码片做规格化内积（点积 ÷ 8）：

A: 1-1+3+1-1+3+1+1 = 8 → 8/8 = +1 → 发送比特1

B: 1-1-3-1-1-3+1-1 = -8 → -8/8 = -1 → 发送比特0

C: 1+1+3+1-1-3-1+1 = 2 → 2/8 ≠ ±1 → 未发送

D: 1+1+3-1+1+3+1-1 = 8 → 8/8 = +1 → 发送比特1

（2）发送比特0即发反码，三个站反码对应位置直接相加（线性叠加）：

A反码: (+1,+1,+1,-1,-1,+1,-1,-1)

B反码: (+1,+1,-1,+1,-1,-1,-1,+1)

C反码: (+1,-1,+1,+1,+1,+1,+1,-1)

空中信号 = (+3,+1,+1,-1,-3,+1,-1,+1)

  • 1200~1400nm频带宽度 = 23.81 THz

  • 1400~1600nm频带宽度 = 17.86 THz

【真题】不归零制和曼彻斯特编码画图：

  • 不归零制(NRZ)： 高电平为1，低电平为0，直接在1和0之间切换
  • 曼彻斯特编码： 每个位中间有跳变。若定义上跳变=0，下跳变=1：
    • 1→中间下跳，0→中间上跳，1→中间下跳，0→中间上跳，0→中间上跳，1→中间下跳

【真题】带宽为4kHz，信噪比为30dB的信道，最大数据传输速率？

信噪比30dB → $S/N = 10^{30/10} = 1000$

$C = W \log_2(1+S/N) = 4000 \times \log_2(1001) \approx 4000 \times 9.97 \approx 39880$ bit/s ≈ 40 kbit/s

3.2 CRC循环冗余校验

必考点：CRC计算（几乎每年都考）

计算步骤：

  1. 设待发送数据为M（k位），生成多项式为P（n+1位，对应n位冗余码）
  2. 被除数 = M后面加n个0（即 $M \times 2^n$）
  3. 被除数对P进行模2除法（异或运算），得到余数R（n位）
  4. 发送的数据 = M拼接R（即 $M \times 2^n + R$）

接收端： 用相同除数P对接收数据做模2除法，余数为0则无差错，否则有差错。

模2运算规则： 加法和减法相同——相同为0，相异为1

【真题】G(x) = x³ + x + 1，待发送信息101010101，求实际发送信息？

除数P = 1011（3+1=4位），n=3

被除数 = 101010101000（后加3个0）

101010101000 模2除 1011：

实际发送：101010101111

【作业题】 假设要发送的数据为1101011011。CRC的生成多项式为P(X) = X⁴+X+1：

（1）试求应添加在数据后面的CRC余码。

（2）如果数据在传输过程中最后一个1变成了0，问接收端能否发现？

（3）若数据在传输过程中最后两个1变成了两个0，问接收端能否发现？

（4）采用CRC检验后，数据在数据链路层是否就变成了可靠的传输？

解答： 根据生成多项式知除数 = 10011（5位），余数应为4位：

（1）被除数 = 1101011011 0000（后加4个0），对10011做模2除法得余数 = 1110，实际发送：11010110111110

（2）接收到的数据变为11010110101110，模2除10011得余数=0011≠0，能发现错误（但不知道哪个比特位出错）

（3）接收到的数据变为11010110001110，模2除10011得余数=0101≠0，能发现错误（但不知道哪个比特位出错）

（4）不是可靠的传输。CRC只能检测比特差错，但传输错误还包括失序、丢失等。数据链路层缺少序号和重传机制，失序时无法重组，丢失时无法重传。

3.3 PPP协议

PPP特点： 简单、封装成帧、透明传输、多种网络协议、面向字节、提供差错检测（不纠错）、全双工

PPP帧格式：

  • 标志字段 F = 7E（同步）| 地址 A = FF | 控制 C = 03 | 协议(2字节) | 信息部分 | FCS(4字节) | 标志 7E

字节填充： 信息中7E→7D5E，7D→7D5D，小于0x20的字符前面加7D

零比特填充： 同步传输时，连续5个1后填入一个0

【作业题】 （1）一个PPP帧的数据部分是7D5EFE277D5D7D5D657D5E（十六进制）。问数据部分出现了几个帧定界符，几个转义符，真正的数据是什么？

（2）PPP协议使用同步传输传送比特串0110111111111100，经零比特填充后变成怎样？

（3）接收端收到PPP帧的数据部分是0001110111110111110110，删除零比特后变成怎样？

解答：

（1）帧定界符7E，转义符7D。接收端遇到0x7D就丢弃，将其后字符+0x20：

  • 7D→5E → 7E（帧定界符）
  • 7D→5D → 7D（转义符）
  • 7D→5D → 7D（转义符）
  • 7D→5E → 7E（帧定界符）

共出现 4个转义符（0x7D），2个帧定界符和2个转义符在真实数据中。

真正数据 = 7EFE277D7D657E

（2）零比特填充：发现连续5个1后填入一个0。

011011111111111100 → 011011111011111000

（3）接收端删除填充位：连续5个1后面的0删除，连续5个1后面的1是帧定界符不删。

0001110111110111110110 → 00011101111111111110

3.4 CSMA/CD协议

必考点：CSMA/CD算法步骤、截断二进制指数退避算法

CSMA/CD要点： 载波监听多点接入/碰撞检测 → “先听后发，边听边发，冲突停发，随机重发”

算法步骤：

  1. 准备发送：适配器从网络层获得分组，组成以太网帧放入缓存
  2. 检测信道：若忙则等待；若空闲并在96bit时间内保持空闲，发送帧
  3. 边发送边检测：
    • 未检测到碰撞 → 发送成功，回到步骤1
    • 检测到碰撞 → 停止发送，发送人为干扰信号（32/48bit），执行退避算法
  4. 重传16次仍不成功 → 丢弃帧并向上报错

截断二进制指数退避算法：

  • 基本退避时间 = 争用期 2τ（10Mbit/s以太网为51.2μs）
  • $k = \min(重传次数, 10)$
  • 从集合 ${0, 1, 2, …, 2^k - 1}$ 中随机取r
  • 重传退避时间 = $r \times 2\tau$ = $r \times 51.2\mu s$
  • 重传16次不成功则放弃

争用期（碰撞窗口）： 端到端往返时延2τ = 51.2μs

  • 以太网最短帧长 = 64字节（512bit），争用期内可发送512bit
  • 帧间最小间隔 = 9.6μs = 96bit时间

信道利用率： 参数 $a = \tau/T_0$（单程时延/帧发送时间），a越小利用率越高

  • 极限利用率：$S_{max} = T_0/(T_0 + \tau) = 1/(1+a)$
  • 以太网利用率达30%即为重载

【作业题】 有两台主机A和B接在800m长的电缆线两端，t=0时各自向对方发送一个帧，帧长度为1500bit。A和B之间有4个转发器，转发时产生20bit时延。传输速率为100Mbit/s，CSMA/CD退避时间中争用期为512bit。发生第一次碰撞后，A选择r=0，B选择r=1。信号传播速率2×10⁸ m/s。忽略人为干扰信号和帧间最小间隔。

（1）计算从A到B（包括4个转发器）的传播时间。

（2）在什么时间B完全收到A发送的帧？

（3）若4个转发器都用交换机代替，交换机存储转发时额外产生20bit处理时延，B完全收到A帧的时间？

解答：

（1）电缆传播时延 = 800/(2×10⁸) = 4μs

4个转发器时延 = 4×(20/10⁸) = 0.8μs

从A到B总传播时延 = 4 + 0.8 = 4.8μs

（2）A的发送时延 = 1500/(100×10⁶) = 15μs

争用期 = 512/(100×10⁶) = 5.12μs

第一次碰撞发生在t≈4.8μs，A选择r=0退避0个争用期，等待5.12μs后重发。A重发时不会再碰撞。

总时延 = 第1次发送到碰撞停止 + 等待空信道 + 第2次发送 + 第2次传播

= 4.8 + 5.12 + 4.8 + 15 + 4.8 ≈ 29.4μs

（3）用交换机替代转发器后：

每个交换机需要存储转发，额外时延 = 转发时延(20bit) + 处理时延(20bit) = 40bit

总时延 = A的发送时延 + 电缆传播时延 + 4个交换机转发时延

= 15 + 4 + 4×(15 + 0.2) = 79.8μs

3.6 扩展以太网与设备对比

重点：集线器、网桥、交换机的异同

设备工作层次特点
转发器/中继器物理层连接不同网段，消除信号衰减失真
集线器物理层多端口转发器，所有端口共享总线带宽，广播域
网桥数据链路层根据MAC帧目的地址转发和过滤，分割冲突域
以太网交换机数据链路层多接口网桥，全双工，同时连通多对端口，自学习建立帧交换表，独占带宽无碰撞

交换机自学习算法：

  1. 收到帧 → 查找帧中源地址在交换表中的项目
    • 无→新增（源地址、进入接口、有效时间）
    • 有→更新
  2. 查找帧中目的地址在交换表中的项目
    • 无→向除进入接口外所有接口广播（泛洪）
    • 有且接口不同→按表转发
    • 有且接口相同→丢弃

碰撞域与广播域：

概念定义
碰撞域（冲突域）两台设备同时发送数据会产生碰撞的区域
广播域一个设备发送广播帧，所有能接收到的设备构成的区域

设备对碰撞域和广播域的影响：

设备工作层次隔离碰撞域隔离广播域
集线器（Hub）物理层❌❌
网桥（Bridge）数据链路层✅❌
交换机（Switch）数据链路层✅（每个端口一个）❌
路由器（Router）网络层✅✅

判断方法：

  • 碰撞域数量：看有多少个独立的"不能同时发送"的区域
    • 集线器的所有端口共享1个碰撞域
    • 交换机的每个端口是1个独立的碰撞域
  • 广播域数量：看有多少个"广播帧无法穿越"的边界
    • 集线器/交换机的所有端口属于同1个广播域
    • 路由器的不同接口属于不同的广播域

3.7 虚拟局域网VLAN

  • 由一些局域网网段构成的与物理位置无关的逻辑组
  • 限制了接收广播的计算机数量，防止广播风暴

3.8 真题与解答

【真题】IEEE802.3局域网传递ASCII信息封装MAC，计算帧有效字节，需要填充多少字节？

若数据部分为n字节：

  • 帧最小长度 = 64字节 = 首部(14字节) + 数据 + FCS(4字节)
  • 数据最小 = 64 - 14 - 4 = 46字节
  • 若n < 46，需填充 46 - n 字节
  • 若n ≥ 46，不需要填充

【真题】10BASE-T争用期51.2μs，报文重传三次后，用截断二进制指数退避算法计算再次准备重传最多需要等待的时间？

第4次重传，重传次数=4，$k = \min(4, 10) = 4$
从 ${0, 1, 2, …, 2^4-1} = {0,1,2,…,15}$ 中取最大值r=15
最多等待时间 = $15 \times 51.2\mu s = 768\mu s$

最低位MF (More Fragment)MF=1 → 后面还有分片（不是最后一片）；MF=0 → 这是最后一片（或未分片）

片偏移（13位）： 表示该分片的数据部分在原始数据报中的起始位置，单位为8字节。例如片偏移=185，表示该片从原始数据的第 185×8=1480 字节开始。

分片规则：

  • 每个分片数据长度必须是8字节的整数倍（因为片偏移单位为8字节）
  • 除最后一个分片外，MF=1；最后一个分片MF=0
  • 每个分片都有完整IP首部，且标识字段相同
  • DF=0才允许分片

4.7 路由选择协议

RIP协议（距离向量/内部网关协议）

重点：RIP路由表更新算法、坏消息传得慢

RIP特点：

  • 仅和相邻路由器交换信息
  • 交换的是自己完整的路由表
  • 按固定时间间隔交换
  • 距离度量=跳数（最大15跳，16=不可达）
  • 使用UDP传送
  • 好消息传播快，坏消息传得慢（收敛时间长）

距离向量算法：
收到地址X的相邻路由器发来的RIP报文后：

  1. 将所有项目的距离+1，下一跳改为X
  2. 若原路由表无该目的网络 → 添加
  3. 若原路由表有该目的网络，且原下一跳=X → 替换
  4. 若原路由表有该目的网络，且原下一跳≠X，新距离更小 → 更新
  5. 3分钟未收到更新 → 标记不可达(16)

  • 经过2段（源→节点1→节点2）概率 = (1-p)p

（3）每个分组平均传送次数×平均链路段数

5.5 TCP三次握手与四次挥手

必考点：三次握手和四次挥手的状态转换

三次握手（建立连接）：

  1. 客户 → 服务器：SYN=1, seq=x（客户端进入SYN-SENT状态）
  2. 服务器 → 客户：SYN=1, ACK=1, seq=y, ack=x+1（服务器进入SYN-RCVD状态）
  3. 客户 → 服务器：ACK=1, seq=x+1, ack=y+1（双方进入ESTABLISHED状态）

四次挥手（释放连接）：

  1. 客户 → 服务器：FIN=1, seq=u（客户进入FIN-WAIT-1）
  2. 服务器 → 客户：ACK=1, seq=v, ack=u+1（服务器进入CLOSE-WAIT，客户→服务器方向已释放，半关闭）
  3. 服务器 → 客户：FIN=1, ACK=1, seq=w, ack=u+1（服务器进入LAST-ACK）
  4. 客户 → 服务器：ACK=1, seq=u+1, ack=w+1（客户进入TIME-WAIT，等待2MSL后进入CLOSED）

【作业题】 TCP协议如何保证可靠传输？

解答：

（1）应用数据分割成TCP认为最适合发送的数据块

（2）TCP对每个数据块编号，接收方确认

（3）TCP首部有检验和字段，检测传输中的变化

（4）接收方有缓存和流量控制（滑动窗口），防止丢失

（5）TCP使用可变大小滑动窗口实现流量控制

（6）拥塞控制：网络拥塞时减少数据发送

（7）停止等待协议：每发一个分组就等待确认

（8）超时重传：发送后启动定时器，未及时收到确认则重发

信道利用率计算（重要）：

发送方从发送第一个比特开始，到收到确认为止为一个发送周期。一个周期中只有发送数据的那段时间在做有用工作，其余时间都在等待，因此：

1. 停止等待协议（发送窗口=1）：

$$U = \frac{T_D}{T_D + RTT + T_A}$$

  • $T_D$：发送一个分组的时间（= 分组长度/发送速率）
  • $RTT$：往返时延
  • $T_A$：确认帧发送时间（通常远小于 $T_D$，可忽略）
  • 利用率很低，大部分时间在等待确认

2. 连续ARQ / 回退N步协议（滑动窗口，发送窗口=n）：

$$U = \frac{n \cdot T_D}{T_D + RTT + T_A}$$

  • n 为发送窗口大小（一次可连续发送的分组数）
  • 当 $n \geq 1 + RTT/T_D$ 时（即发送窗口 ≥ 信道容量/带宽时延积），发送方可连续发送不中断，$U \approx 1$（利用率达到100%）
  • 窗口越大利用率越高，但受接收窗口和网络拥塞限制

对比理解： 停止等待是 n=1 的特例。滑动窗口通过批量发送将等待时间"重叠"掉，从而大幅提升利用率。

【作业题】 假定要在网络上传送1.5MB文件，分组长度1KB，RTT=80ms。建立TCP连接时间=2×RTT=160ms。计算接收方收完最后一个比特的时间：

（1）数据发送速率10Mbit/s，可连续发送。

（2）速率10Mbit/s，每发完一个分组后要等一个RTT。

（3）速率极快忽略发送时间，每个RTT只能发20个分组。

（4）速率极快，第1个RTT发1个，第2个RTT发2个，第n个RTT发2ⁿ⁻¹个。

解答： 1.5MB = 1.5×2²⁰ = 1572864字节，每分组1KB，共 1572864/1024 = 1536个分组。发送时延 = 8×1.5×2²⁰/(10×10⁶) ≈ 1.258s。传播时延 = 40ms。

（1）总时延 = TCP连接时延 + 发送时延 + 传播时延 = 160 + 1258.29 + 40 = 1458.29ms

（2）1536个分组有1535个等待间隔（最后一个无需等待），总时延 = 160 + 1258.29 + 1535×80 + 40 ≈ 124258.29ms = 124.26s

（3）每RTT发20个，需1536/20 = 76.8，即77批（76整批+最后一批16个），总时延 = 160 + 76×80 + 40 = 6280ms = 6.28s

（4）第n个RTT结束共发送1+2+4+…+2ⁿ⁻¹ = 2ⁿ-1个分组。n=10时共1023个，剩余513个在第11个RTT发送。总时延 = 160 + 10×80 + 40 = 1000ms = 1s

5.7 TCP超时重传时间计算

必考点：RTTs和RTO计算

加权平均往返时间： $RTT_S = (1-\alpha)(旧RTT_S) + \alpha(新RTT样本)$

  • 推荐α=1/8

RTT偏差加权平均值： $RTT_D = (1-\beta)(旧RTT_D) + \beta|RTT_S - 新RTT样本|$

  • 推荐β=1/4

超时重传时间： $RTO = RTT_S + 4 \times RTT_D$

注意： 报文段重传时不采用其往返时间样本

【真题】已知：旧的RTTs=30ms，新的RTT样本=26ms，旧RTT_D=5ms，α=1/8，β=1/4。求新RTTs和新RTO。

$RTT_S = (1 - 1/8) \times 30 + 1/8 \times 26 = 7/8 \times 30 + 1/8 \times 26 = 26.25 + 3.25 = 29.5$ ms

$RTT_D = (1 - 1/4) \times 5 + 1/4 \times |29.5 - 26| = 3.75 + 0.875 = 4.625$ ms

$RTO = 29.5 + 4 \times 4.625 = 29.5 + 18.5 = 48$ ms

【作业题】 RTT当前值30ms，随后应答分别在26、32、24ms到来，α=0.9。计算新RTT估算值。

解答： $RTT_S = \alpha \times RTT_{S旧} + (1-\alpha) \times RTT_{样本}$

$RTT_1 = 0.9 \times 30 + 0.1 \times 26 = 27 + 2.6 = $ 29.6ms

$RTT_2 = 0.9 \times 29.6 + 0.1 \times 32 = 26.64 + 3.2 = $ 29.84ms

$RTT_3 = 0.9 \times 29.84 + 0.1 \times 24 = 26.856 + 2.4 = $ 29.256ms

【作业题】 TCP建立连接时RTO=6s：

（1）收到连接确认报文段，RTT样本值1.5s，计算RTO。

（2）发送数据报文段收到确认，RTT样本值2.5s，计算RTO。

解答：

（1）初次测量：$RTT_S(1) = 1.5s$，$RTT_D(1) = RTT(1)/2 = 0.75s$

$RTO(1) = 1.5 + 4 \times 0.75 = $ 4.5s

（2）$\alpha = 0.125$，$\beta = 0.25$（RFC6298）

$RTT_S(2) = (1-0.125) \times 1.5 + 0.125 \times 2.5 = 1.625s$

$RTT_D(2) = (1-0.25) \times 0.75 + 0.25 \times |1.625 - 2.5| = 13/16 = 0.8125s$

$RTO(2) = 1.625 + 4 \times 0.8125 = $ 4.875s

5.8 TCP流量控制与拥塞控制

流量控制

  • 通过滑动窗口机制实现，让发送方发送速率不要太快
  • 发送窗口不超过接收窗口大小
  • 糊涂窗口综合征： 接收方缓存满→应用每次读1字节→窗口设为1字节→效率极低
    • 解决：接收方等待缓存有足够空间再发送确认

拥塞控制

必考点：拥塞窗口cwnd变化、慢开始、拥塞避免、快重传、快恢复

四种算法：

算法触发条件cwnd变化ssthresh变化
慢开始cwnd < ssthresh每个RTT加倍不变
拥塞避免cwnd ≥ ssthresh每个RTT加1不变
超时检测到超时cwnd=1，执行慢开始ssthresh = cwnd/2
快重传+快恢复收到3个重复确认cwnd = ssthresh（=原cwnd/2）ssthresh = cwnd/2

关键公式：

  • $cwnd \leq ssthresh$ → 慢开始（指数增长）
  • $cwnd \geq ssthresh$ → 拥塞避免（线性增长）

6.2 文件传输协议FTP

FTP特点：

  • 使用TCP可靠传输
  • 控制连接（端口21）：传输FTP命令（持久连接）
  • 数据连接（端口20）：传输文件内容（每次传输后关闭）
  • 服务器由主进程+从属进程组成
  • 主进程负责接受新请求，从属进程处理单个请求

FTP与TFTP区别：

对比项 FTP TFTP
传输协议 TCP UDP
可靠性 高 低
功能 完整文件传输 简单文件传输
连接 控制连接+数据连接 单一连接

【作业题】 简述FTP的工作过程，为什么FTP的控制信息是带外传送的？

解答：

FTP工作过程：服务器端主进程打开端口21（熟知端口），等待客户端连接请求。当有连接请求到达时，主进程启动从属进程（控制进程），建立控制连接处理请求，主进程继续监听其他请求。控制连接持续存在。当需要传输文件时，创建另一个从属进程（数据进程），建立数据连接（端口20），传输完毕后关闭数据连接。

FTP使用分离的控制连接和数据连接，因此控制信息是带外传送的（控制信息与数据分开传输）。

6.5 DHCP协议

重点：DHCP工作过程（四步）

DHCP（动态主机配置协议）： 即插即用连网，自动分配IP地址

DHCP工作过程：

  1. 发现（DISCOVER）： 客户从UDP端口68广播发送（目的IP=255.255.255.255，源IP=0.0.0.0）
  2. 提供（OFFER）： 服务器从UDP端口67广播/单播回应，提供IP地址等配置
  3. 请求（REQUEST）： 客户选择其中一个服务器，发送请求报文
  4. 确认（ACK）： 服务器确认，IP地址绑定完成

租用期管理：

  • T1 = 0.5T（租用期过半时请求续租）
  • T2 = 0.875T（服务器不响应时再次请求）
  • 到期仍未续租→释放IP地址，重新申请

【作业题】 DHCP协议用在什么情况下？当一台计算机第一次运行引导程序时，其ROM中有没有IP地址、子网掩码或DNS服务器地址？

解答：

DHCP（动态主机配置协议）用于主机加入新网络时自动获取IP地址等配置信息，实现即插即用连网。除普通主机外，还可用于无盘工作站。

计算机第一次运行引导程序时，其ROM中没有IP地址、子网掩码或DNS服务器地址——这些是通过软件配置的逻辑地址（软件地址）。只要网络上有DHCP服务器，计算机就可以通过广播方式发送发现报文，由DHCP服务器单播提供报文，从而获得IP地址等配置信息。

静态文档 事先编写好，内容固定不变
动态文档 每次请求时由服务器程序实时生成

6.7 MIME

MIME（多用途互联网邮件扩展）： 解决SMTP只能传送ASCII文本的限制，使电子邮件可以传送各种非文本数据（图像、音频、视频等）。在邮件首部增加MIME-Version、Content-Type等字段。

【作业题】 假设数据为：110011001000000100111000

（1）对该数据进行Base64编码，得出传送的ASCII数据是什么？编码开销多大？

（2）如对该数据进行quoted-printable编码，得出的ASCII数据是什么？编码开销多大？

解答：

（1）Base64编码步骤：

① 24位划分为4个6位组：

110011 001000 000100 111000

② 查表：110011(51)→z，001000(8)→I，000100(4)→E，111000(56)→4

Base64编码 = zIE4

编码开销 = 4/3 - 1 ≈ 33.3%

（2）quoted-printable编码：前两个字节是汉字（非ASCII），需转换；第三个字节是ASCII字符8不变。

第一字节 11001100 → 十六进制 CC，第二字节 10000001 → 十六进制 81

编码结果 = =CC=818（每个非ASCII字节→等号+两位十六进制）

编码开销 = 6/3 - 1 = 100%（原3字节变6字节）

【真题】HTTP/1.0无状态的含义和好处？

  • 含义：服务器不保留关于客户的状态信息，每个请求独立处理
  • 好处：简化服务器设计，减轻服务器存储和管理负担，提高可扩展性

【真题】对于一个具体域名写出迭代解析过程。

  1. 主机向本地域名服务器发送查询请求
  2. 本地域名服务器向根域名服务器发送查询请求
  3. 根域名服务器返回对应的顶级域名服务器地址
  4. 本地域名服务器向顶级域名服务器发送查询
  5. 顶级域名服务器返回授权域名服务器地址
  6. 本地域名服务器向授权域名服务器发送查询
  7. 授权域名服务器返回IP地址
  8. 本地域名服务器将IP地址返回给主机

【作业题】 下图表示各应用协议在层次中的位置：

（1）为什么有的应用层协议用TCP，有的用UDP？

（2）为什么MIME画在SMTP之上？

（3）为什么路由选择协议RIP放在应用层？

解答：

（1）TCP面向连接、可靠；UDP无连接、尽最大努力、不可靠。需要可靠性的应用用TCP（如HTTP、FTP、SMTP），需要实时性和简单的应用用UDP（如DNS、RIP、DHCP）。使用UDP的协议可靠性可由应用层自身编码实现。

（2）SMTP是基础邮件传输协议，MIME是SMTP的扩展，将非ASCII邮件转换成ASCII后用SMTP传输。MIME使用SMTP，是SMTP的更高层，而非替代SMTP。

（3）RIP需要定时与相邻路由器交换路由表信息，该信息封装在UDP数据报中。RIP报文是不同路由器上进程间交换信息的单位，因此被放在应用层。
