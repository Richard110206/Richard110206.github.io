LLM From Scratch

目前主要跟着这个项目学习：glm-5.3-flash-from-scratch

推荐资料

  • LLMs-from-scratch：《Build a Large Language Model (From Scratch)》配套仓库，从零一步步搭 GPT
  • nanoGPT：Karpathy 的极简 GPT 训练实现，读懂主干架构的最佳参考
  • minbpe：Karpathy 的极简 BPE 分词器实现，学 Tokenizer 用
  • train-llm-from-scratch：在自定义数据集上从零训练 LLM 的完整流程

学习路线

  1. Tokenizer：先弄懂分词（BPE），理解文本是怎么变成 token 的，配合 minbpe 看实现
  2. Embedding → Attention → Transformer：模型主干这一套，从词嵌入、自注意力机制到 Transformer 整体架构，参考 nanoGPT 和 LLMs-from-scratch
  3. SFT：在预训练模型的基础上做监督微调
  4. 模型后续点：训练跑通之后，再深入一些模型的改进方向

Tokenizer：手动实现一个简单分词器

从分词器开始，先手动实现一个最简单的版本，整体思路是：

  1. 预设一个数据集，作为我们的语料库；
  2. 对语料库做字符串处理，按标点和空格把内容切分开，切出来的 token 只有单词和标点两类；
  3. 对所有 token 去重——词表里不可能让同一个单词对应两个不同的 token ID；
  4. 再做 sort 排序，排序对程序本身意义不大，主要是方便查看；
  5. 最后给每个 token 一一编号，构造出「token → token ID」的键值对，词表（vocab）就建好了。

之后编码走的还是同样的流程：把句子拆分成单个的 token（通常是单词和标点），再拿它们去查前面构造好的词表，按键值对找到每个单词对应的 token ID，把数字输出出来。

测试的时候，可以额外加一段不属于语料库的句子进来。这时会发现有些词在词表里查不到——这个词表太小，没办法涵盖所有单词，直接查就会报错。所以一般还会往词表里加几个特殊 token：

  1. <|endoftext|>：标记文本的开始与结束，用来分隔两段不相关的文本；
  2. <|unk|>：词表里识别不了的词统一归为这一类，放在词表末尾。

BPE 分词器（tiktoken）

上面是我们手动实现的分词器，实际使用中也可以直接用现成的 BPE（Byte Pair Encoding，字节对编码）分词器来完成。它的好处是：

  1. 词表更大、分词更精细：不再是我们手写的那种小词表，比如 cl100k_base 就有约 10 万个 token；
  2. 不会卡在不认识的单词上：手写版本遇到词表外的词只能归到 <|unk|>，而 BPE 会把不认识的词拆成更小的子词单元。比如 unfamiliar 可以把 un 拆出来，unhappiness 可以拆成 un / happi / ness 这样的几部分——一个长单词总能拆到词表里已有的单元为止（极端情况下拆到字节级别），所以任何新词都能表示出来，也就不需要 <|unk|> 了。
